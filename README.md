# MISTERCHIP — платформа электроники

MISTERCHIP — развивающийся проект на Django: каталог конкретных моделей
электроники, поиск и сравнение характеристик, учётные записи, статьи и DIY-проекты.
Репозиторий предназначен для знакомства с исходным кодом и локального запуска.

Описание ниже относится к коду в `main`. Оно не подтверждает состояние
отдельного работающего сервера.

## Что уже реализовано

| Часть проекта | Возможности в `main` |
| --- | --- |
| Каталог | Разделы, производители, конкретные модели и ссылки на документацию изготовителей. |
| Характеристики | Настраиваемые типы товаров, типизированные значения, обязательные поля и нормализация предусмотренных единиц измерения. |
| Поиск и сравнение | Поиск по модели, названию, артикулу и бренду; фильтры; сравнение 2–4 моделей одного типа. |
| Учётные записи | Регистрация, подтверждение email, вход, восстановление пароля и несколько бизнес-ролей у одной учётной записи. |
| Статьи и DIY | Редакционные материалы, проекты пользователей и их связи с моделями каталога. |
| Администрирование | Django Admin и форма настройки характеристик конкретной модели. |

**Market разрабатывается отдельно:** магазины, предложения продавцов и обращения
покупателей находятся в [черновике PR #1](https://github.com/nikitinlaw/misterchip/pull/1)
и пока не включены в `main`. Сравнение в основной ветке относится к техническим
характеристикам моделей.

## Технологии

- Python 3.13 и Django; точные версии зависимостей — в [requirements.txt](requirements.txt).
- PostgreSQL 16 и Redis 7 в Docker Compose.
- Серверные Django-шаблоны; Gunicorn и WhiteNoise для серверного окружения.
- GitHub Actions для автоматических проверок.

## Быстрый локальный запуск

Понадобятся Git и Docker с командой `docker compose`, поддерживающей
`up --wait`. Команды рассчитаны на macOS, Linux или WSL.

```bash
git clone https://github.com/nikitinlaw/misterchip.git
cd misterchip
cp .env.example .env
docker compose build web
```

**До первого запуска базы** задайте в `.env` собственные случайные
`DJANGO_SECRET_KEY` и `DB_PASSWORD`.
[Как сгенерировать значения](docs/LOCAL_DEVELOPMENT.md#2-задать-локальные-ключ-и-пароль).
Сохраните `DJANGO_DEBUG=1` и остальные настройки локального режима из примера.

```bash
docker compose up -d --wait db redis
docker compose run --rm --no-deps web python manage.py migrate --noinput
docker compose run --rm --no-deps web python manage.py seed_demo_catalog
docker compose up -d web
```

Откройте **http://127.0.0.1:8000/**.
Для административного доступа создайте собственную учётную запись:

```bash
docker compose exec web python manage.py createsuperuser
```

Административная панель: http://127.0.0.1:8000/admin/.
Общего административного пароля в проекте нет.
[Полная инструкция и разбор ошибок](docs/LOCAL_DEVELOPMENT.md).

Для обычной остановки используйте `docker compose down`: данные сохраняются
в volumes. Локальная конфигурация слушает только `127.0.0.1` и не предназначена
для размещения в открытой сети. Письма разработки выводятся в журнал контейнера;
они не отправляются настоящим адресатам.

## Демонстрационные данные и модель каталога

`seed_demo_catalog` создаёт два типа товаров и четыре модели:
Kingston FURY Beast `KF552C40BB-16`, `KF556C40BB-16`,
YAGEO `RC0603FR-071KL`, `RC0603FR-0710KL`.
В карточках хранятся ссылки на официальные спецификации.
Продавцы, цены, остатки, пользователи и редакционные материалы этой командой
не создаются.

Команда также импортирует 11 разделов и 373 позиции из
[data/trademark_goods_ru948080.csv](data/trademark_goods_ru948080.csv).
Это справочник наименований товаров из свидетельства RU № 948080:
`TrademarkGood` хранит позицию справочника, а `Product` — конкретную
техническую модель. Эти сущности разделены.

Повторное заполнение не дублирует модели и сохраняет редакторские изменения
их описаний и характеристик. Отдельный `import_goods` для quickstart не нужен.
При работе только со справочником команда `import_goods --check-only`
проверяет CSV без записи, а `import_goods` загружает или обновляет его позиции.

## Проверки

```bash
docker compose exec web python manage.py check
curl --fail --silent --show-error http://127.0.0.1:8000/healthz/
```

Ответ `ok` подтверждает доступ к PostgreSQL и Redis. Миграции и заполнение
каталога проверяйте также по страницам из таблицы выше.

В GitHub Actions предусмотрены два вида проверки:

- [Django checks](.github/workflows/tests.yml): миграции, системные проверки,
  серверные сценарии, сборка статики и тесты приложения.
- [Local demo startup](.github/workflows/local-demo.yml): новая база и Redis,
  сборка Docker-образа, миграции, заполнение каталога и HTTP-проверка страниц
  по инструкции локального запуска.

Результаты конкретных запусков доступны на
[странице Actions](https://github.com/nikitinlaw/misterchip/actions).
